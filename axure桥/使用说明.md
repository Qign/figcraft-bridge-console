# FigCraft → Axure 转换桥（FigCraft 内选中画板 → 一键复制 → Axure 粘贴）

## 先说清一件事：为什么不是"应用内插件面板"

FigCraft 有插件体系（`figcraft-plugin.json` + `plugin.run` / `plugin.ui`），但插件沙箱里**拿不到系统剪贴板**——实测它自带的复制（`edit.copy`）只写应用内部剪贴板，系统剪贴板上什么都没有。而"粘到 Axure"必须由**外部进程**往 Windows 系统剪贴板写 `// axvg`。

所以最终接法是：**一个常驻后台的转换桥 + 一个全局热键**。用起来的感觉就是"在 FigCraft 里选中画板，按一下键，去 Axure 粘"——没有窗口、没有弹窗、不用选文件。

## 用法（三步）

1. 用 **`启动FigCraft(带转换桥).lnk`** 打开 FigCraft（必须以 `--control 47900` 方式启动，桥要读实时数据）
2. 在 FigCraft 里选中画板（可多选；选中的是卡片级 Frame 就只转那张卡；选中的是普通图层会自动转它所在的画板）
3. 按 **Ctrl+Alt+C** → 屏幕下方弹出提示（组/文本/形状数量）→ 切到 Axure 画布空白处 **Ctrl+V**

> 桥需要常驻：双击 **`启动转换桥(常驻热键).lnk`**（无窗口，开机后手动点一次即可；想开机自启可把这个快捷方式拖进 `shell:startup`）。

## 开关：启用 / 暂停 / 停用

FigCraft 插件做不了这个开关（插件是 WASM 沙箱，没有文件、没有网络、没有进程能力，连"启动别的程序"这条命令都在黑名单里），所以开关做成三个层级，按使用频率从高到低：

| 你要的效果 | 操作 | 代价 |
|---|---|---|
| 此刻不想被打搅，但过会儿还要用 | 按 **Ctrl+Alt+S** | 进程不退，只停止响应 Ctrl+Alt+C；再按一次恢复。提示条会确认 |
| 这段时间完全不用了 | 双击 **`停用桥.bat`** | 进程结束，两个热键全部失效，剪贴板不再被改动 |
| 又要用了 | 双击 **`启用桥.bat`** | 后台静默拉起，1 秒内可用；已启动时重复双击不会起两个 |

暂停状态记在 `%TEMP%\figcraft2axure\paused.flag`，**重启桥后依然有效**——所以"暂停着过夜、明天打开电脑"不会突然复活去改你的剪贴板；想恢复按 Ctrl+Alt+S，或跑一次 `启用桥.bat` 也会自动清掉暂停。

> 进程管理只精确匹配命令行含 `figcraft_axure_bridge.py` 的 `python.exe` / `pythonw.exe`，并排除 `--toast` 提示子进程，不会误伤机器上别的 python 程序。
>
> 同一时刻只允许一个桥实例（互斥体保护）：重复启动会被拦下并提示"已经在运行"，不会再出现两个进程抢热键、旧进程占着热键但连不上 FigCraft 的情况。

## 文件清单

| 文件 | 作用 |
|---|---|
| `figcraft_axure_bridge.py` | 主程序：控制通道取选中 → 转 axvg → 写系统剪贴板（纯标准库，无第三方依赖） |
| `axvg_tpl.json` | axvg 三种图元模板（组/文本/形状），必须与主程序同目录 |
| `启动FigCraft(带转换桥).lnk` | 带 `--control 47900` 启动 FigCraft |
| `启动转换桥(常驻热键).lnk` | 用 pythonw 静默启动桥，监听 Ctrl+Alt+C |
| `启用桥.bat` | 一键启用（已在运行则只清暂停状态） |
| `停用桥.bat` | 一键停用（只杀本桥进程） |
| `查看状态.bat` | 一眼看清：桥在不在跑、有没有暂停、FigCraft 连没连上 |
| `bridge_ctl.py` | 启停/状态管理，供三个 bat 调用，也可命令行直接用 |
| `调试运行.bat` | 带控制台运行，用于看输出／排查 |

## 命令行

```
figcraft_axure_bridge.py                  # 常驻，监听热键（默认 ctrl+alt+c）
figcraft_axure_bridge.py --once           # 立即转换当前选中，打印结果后退出（调试）
figcraft_axure_bridge.py --port 48000     # 换控制端口
figcraft_axure_bridge.py --hotkey ctrl+alt+x
figcraft_axure_bridge.py --depth 40       # 图层树读取深度（默认 30）
figcraft_axure_bridge.py --no-clip        # 只生成文件、不动剪贴板
figcraft_axure_bridge.py --pause-hotkey ctrl+alt+s
figcraft_axure_bridge.py --pause / --resume / --status
python bridge_ctl.py start|stop|status|pause|resume
```

输出文件（调试用，不参与粘贴）：`%TEMP%\figcraft2axure\<文件名>_<画板id>.txt`
运行日志：`%TEMP%\figcraft2axure\bridge.log`

## 已验证

- 与旧版（文件模式）产出的全量包逐字段比对：**结构 0 差异**，仅颜色浮点末位精度差 3.3e-08
- 页面1 全量：组 6 / 文本 60 / 形状 37，211.9 KB，剪贴板严格 2 行（`// axvg` + 单行 JSON）
- 多选合并、卡片级 Frame 单独转换、选中文本图层自动上溯画板、空选区提示，四种模式均通过

## 已知限制

- **图片（imageMap）不支持**：图片图元会被跳过并在日志里告警；渐变、母版同样未实现
- 圆角按 8 点贝塞尔还原（k=0.5523），椭圆按 4 段贝塞尔，与 Axure 原生圆角矩形视觉一致但不能反向编辑圆角数值
- 粘贴不带 Axure 交互事件（协议本身不承载）
- 转换会**替换系统剪贴板内容**（这正是它工作的方式）

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| **没启用，按热键却还有提示** | 说明桥进程还活着（提示本身就是它发的）。未启用时按热键应当毫无反应。先双击 `查看状态.bat` 确认，再双击 `停用桥.bat`；若停用后仍有提示，说明被安全软件拦住了杀进程，去任务管理器结束 `pythonw.exe` / `python.exe` |
| **双击启用桥后仍提示未启用 / 只闪一下** | 旧版本会先匹配到残留进程就判定"已在运行"直接退出。已修正：现在会复用或重建，并明确打印状态；窗口也不再一闪而过（改为按键关闭） |
| 按热键提示"FigCraft 还没打开（端口 47900 无响应）" | 桥在正常运行，只是 FigCraft 没带 `--control` 启动。彻底退出 FigCraft，改用 `启动FigCraft(带转换桥).lnk` |
| 按热键提示"转换桥已暂停" | 之前按过 Ctrl+Alt+S，暂停标记还没清。再按一次 Ctrl+Alt+S，或双击 `启用桥.bat` |
| 按热键提示"热键被其他程序占用" | 同类软件（截图、录屏、输入法）抢了 Ctrl+Alt+C。用 `--hotkey ctrl+alt+x` 换键 |
| 双击 lnk 后仍没端口 | 系统里已有 FigCraft 实例在跑（单实例会激活旧窗口）。先全部退出再点 lnk |
| 热键无反应 | 见上条，或桥没启动（`查看状态.bat` 会直接告诉你） |
| 粘土报"错误报告" | 剪贴板内容被其他程序改过（不是纯 axvg 两行）。重新按一次热键 |
| 想换端口 | 两边同时改：lnk 的 `--control 新端口` + 桥的 `--port 新端口` |
| 担心它误改剪贴板 | 长时间不用就双击 `停用桥.bat`；临时避让按 Ctrl+Alt+S。暂停时按热键只提示、不碰剪贴板（已验证） |
